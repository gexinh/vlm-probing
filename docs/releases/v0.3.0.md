# v0.3.0: Model Coverage and Documentation

[Home](../../README.md) / [Documentation](../README.md)

Date: 2026-09-19. Previous release: v0.2.0, commit
`6f52a83707b778cbe127afbce995a8a61cd9d6bc`.

## Goal

Make the repository an English documentation entry point with concise onboarding,
per-model usage, and per-method API guides. Use Qwen3.5-4B as the primary example
and expand the automatic adapter set to common small VLMs.

## Changes from v0.2.0

| Area | v0.2.0 | v0.3.0 |
| --- | --- | --- |
| README | Long walkthrough with implementation and research sections | Quick Start, linked model/method indexes, brief structure, reference index |
| Documentation | Shared API plus mixed-language research/catalog files | Seven VLM guides, a Llama control guide, 18 method guides, common API, English paper index |
| Native VLM support | Qwen2.5-VL | Qwen3.5, Qwen3-VL, Qwen2.5-VL, Qwen2-VL, SmolVLM/Idefics3, InternVL, LLaVA |

| Hybrid attention | Not supported | Qwen3.5 residual probes on all layers, standard-attention methods on explicit full-attention layers |
| Propagation validation | Nonconsecutive layers rejected during execution | Capability report and factory reject attention gaps before a model run |
| Pretrained validation | None | Image-path checks on Qwen3.5-4B, Qwen2.5-VL-3B, and SmolVLM-256M |

The Hugging Face adapter uses one shared execution implementation with exact-class
contracts. Qwen3.5's gated attention output and `1 + weight` RMSNorm gain are handled
explicitly. SmolVLM-256M is routed through its actual `Idefics3ForConditionalGeneration`
class, verified from the official checkpoint. Processor-returned multimodal token
types, image masks, grids, and positions participate in aligned-intervention checks.

Removed obsolete research reports, JSON catalogs, and superseded mixed-language
version/method notes from the current tree. Relevant method sources are consolidated
in the [paper index](../REFERENCES.md); prior documents remain recoverable in Git.

## Expected behavior

- The same `Prober(model)` and `.run(inputs)` workflow works across the seven
  registered VLM families.
- Final-layer Logit Lens agrees with the model readout within execution precision.
- Self-patching has zero effect; actual image changes can alter downstream scores.
- Token selections follow processor-expanded coordinates, including variable image
  grids and padding.
- Head projections sum to the bias-free attention output.
- Unsupported attention editing and hybrid propagation fail explicitly.
- Calibration remains separate from inference. Architecture support does not imply
  that all methods were calibrated or benchmarked on every pretrained checkpoint.

## Validation

Environment: Python 3.12, PyTorch `2.6.0+cu124`, Transformers `5.3.0`.
Pretrained checks used one NVIDIA A100 80GB with bf16 and eager attention.

### Offline architecture tests

The complete suite passed **79 tests** with Transformers 5.3.0. The 4.57.6
compatibility run passed **71 tests**, with the eight new-architecture tests
skipped as intended.

The new matrix covers real tiny vision towers, projectors, language decoders,
all six lens methods, four residual causal methods, available attention methods,
frozen-parameter gradients, readout equality, variable visual layouts, padding,
head projections, self-patching, nontrivial patch effects, and hook preservation.
A separate regression check ensures Qwen3-VL residual captures include DeepStack
visual additions. Qwen3.5 uses a three-linear/one-full-attention test stack,
including Jacobian/attribution gradients through downstream linear-attention
blocks with the PyTorch fallback. Propagation is rejected before inference.

All **18 method-page example snippets** were executed with their documented CPU
setup, including fitted-artifact save/load. Documentation code blocks were parsed
and all 35 documentation pages passed relative-path/anchor checks. Editable
installation and the v0.3.0 wheel build succeeded. The official processors for all seven checkpoints
were exercised with image+chat inputs; only metadata/tokenizers were downloaded
for the four checkpoints whose weights were not run.

### Pretrained image-path checks

[Executable validation](../../examples/pretrained_smoke.py) uses a red square on
a white background and a one-word color question. It checks selected Logit Lens
layers, EmbedLens coordinates, one attention profile, and layer-0 visual patching.
The metric is the `" red"` minus `" blue"` token-logit margin; both labels were
verified to be single tokens for each tokenizer.

| Check | Qwen3.5-4B | Qwen2.5-VL-3B-Instruct | SmolVLM-256M-Instruct |
| --- | --- | --- | --- |
| Native class | Qwen3_5ForConditionalGeneration | Qwen2_5_VLForConditionalGeneration | Idefics3ForConditionalGeneration |
| Language layers | 32 | 36 | 30 |
| Sequence tokens | 89 | 41 | 1,146 |
| Visual slots identified | 64 | 9 | 1,088 |
| Standard attention layers | 3, 7, 11, 15, 19, 23, 27, 31 | 0–35 | 0–29 |
| Max absolute final-readout difference | 0.03125 | 0.0625 | 0.0 |
| Self-patch score change | 0.0 | 0.0 | 0.0 |
| Image-patch score change | +9.75 | +10.9375 | +14.625 |
| Attention profile finite | Yes | Yes | Yes |
| Peak PyTorch allocated GPU memory | 11.466 GiB | 8.463 GiB | 3.143 GiB |

The bf16 readout check allows `atol=0.25, rtol=0.02`: selecting a token before the
vocabulary projection can change matrix-multiplication rounding. Qwen controls
zero processed image values; SmolVLM controls invert them because its native model
treats zero tiles as padding. These are functional integration checks, not
hallucination benchmarks or evidence of task-quality improvements.

The pretrained runs did not fit Tuned/Attention/Jacobian lenses, run full-gradient
attribution, or exercise all model/backend combinations. Those method contracts
were tested on the small architectures. Video, multi-image prompts, quantized
weights, sharding/offload, and compiled models remain outside this validation.

## Reproduce

From the repository root:

```bash
pip install -e ".[transformers]"
python -m unittest discover -s tests -v
python examples/prober_quickstart.py
python examples/hf_model_matrix.py
python examples/pretrained_smoke.py /path/to/Qwen3.5-4B --device cuda:0
python examples/pretrained_smoke.py /path/to/Qwen2.5-VL-3B-Instruct --device cuda:0
python examples/pretrained_smoke.py HuggingFaceTB/SmolVLM-256M-Instruct --device cuda:0
```

The first two pretrained runs used existing local model directories. The third
used the official Hugging Face checkpoint. The script prints structured metrics
to stdout and does not train the model.
